このサイトの安全対策

「安心して開けるリンク集」であるために、このサイトが行っている対策と点検の手順です。
運用：Yutaka Yoshioka（吉岡有隆）・非営利

基本の考え方：持たない・書き込ませない・検査で止める

  • 持たない：サーバー・ログイン・入力フォーム・APIキーなどの秘密情報・閲覧した人のデータを持たない静的なサイトです。アクセス解析や広告もありません。
  • 画面で実行させない：外部への通信と、ページに直接書いたスクリプトの実行を、ブラウザの仕組み（コンテンツ・セキュリティ・ポリシー）で禁止しています。表示する文字はすべて「文字」として扱い、HTML として解釈しません。例外は、地震の分野を開いているあいだに米国地質調査所（USGS）の公開データを読み込む1か所だけです。
  • 自動の更新に生成AIを使わない：感染症・ITセキュリティ・地震などの自動取得は、決まった手順のプログラムだけで行います。取得した文章をAIに読ませません。
  • 書き込ませない：自動の更新はリポジトリ（サイトの元のデータ）に書き込む権限を持ちません。AIが提案できる変更は、掲載内容の2つのファイルだけです。
  • 検査で止める：公開の前に、個人情報・秘密情報の混入、許可していないリンク先、見えない文字、悪用されうる細かい情報などを機械的に検査し、失敗したら公開しません（公開中のサイトは前回の内容のまま残ります）。
  • 人が最後に決める：変更を作る者と確かめる者を分け、運用者が差分を見てから取り込みます。検査に通ったことは安全の証明ではないため、人の確認を前提にしています。

リンクの安全

  • 政府・公的機関・国際機関・査読付き学術誌など、決めた許可リストの組織のページだけを載せます。民間・個人のサイト、短縮URL、広告のリンクは載せません。
  • 新しいリンクは、公式のページであること、別のドメインへ転送されないこと、改ざんの兆候がないことを確かめ、確認の記録があるものだけを表示します。
  • 週1回の自動確認：証明書の不備・リンク切れ・転送・改ざんの兆候（不正な埋め込みや、AIへの指示のような文）を調べます。全部で800件を超えるため、4つのまとまりを1週に1つずつ調べ、4週で一巡します。危険なものは運用者に知らせ、掲載から外すか公式の新しいURLに直します。

点検の手順（定期）

  • 毎日2回：公開のたびに、データの検査・個人情報の検査・コミットの検査・リポジトリの設定の検査・自己テストを行い、1つでも失敗したら公開しません。
  • 毎週：リンクの自動確認（上記）と、公式のセキュリティ情報（GitHub・Node.js・JPCERT/CC・IPA など）の確認、運用者が GitHub の画面で行う点検（見覚えのないログイン・連携・PR・ブランチが無いか など）。
  • 毎月（急な病気・けがのページ）：命にかかわる情報のため、毎月最初の週に自動の検査でリンク先の安全を調べたあと、運用者（人）がすべてのリンク先を開いて内容を確かめます。まだ人が確認していないリンクは載せず「確認待ち」と表示します。確認の時期を過ぎたリンクは消さずに残し、運用者に知らせが届きます。救急の電話相談（＃7119）の実施地域も、消防庁の一覧と照らし合わせます。
  • 最後の更新から45日：GitHub は60日間更新の無いリポジトリの定時の処理を止めるため、45日を過ぎたら運用者に知らせます。
  • 新しい事例が出たとき：内容を確かめ、このサイトに関係するかを調べて、必要なら対策します。下の「最近の事例と対応」と、このサイトの更新のセキュリティ対策に記録します。

点検にはAIの手伝いも使いますが、AIは「提案する者」で、決めるのは運用者です。AIが自分で行った点検を「独立した監査」とは呼びません。

脆弱性を見つけたとき

このサイトの脆弱性を見つけた場合は、公開の場に書かず、security.txt にある連絡先（GitHub の非公開の脆弱性報告）からお知らせください。ほかの製品の脆弱性は、製品の提供元や、日本では IPA（情報処理推進機構）の届出窓口へご連絡ください。

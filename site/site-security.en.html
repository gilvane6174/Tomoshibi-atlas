How this site stays safe

The measures and review routine that keep Tomoshibi Atlas a link collection you can open with confidence.
Run by Yutaka Yoshioka (non-profit)

Principles: hold nothing, allow no writes, stop on failed checks

  • Hold nothing: a static site with no server, login, forms, API keys or other secrets, and no visitor data. No analytics or ads.
  • Run nothing in the page: outside connections and inline scripts are blocked by the browser's Content Security Policy. All text is shown as text, never as HTML. The only exception is loading the U.S. Geological Survey's public earthquake data while the Earthquakes section is open.
  • No generative AI in automatic updates: automatic retrieval uses fixed programs only; retrieved text is never given to an AI.
  • No write access: automatic updates cannot write to the repository. AI can only propose changes to two content files.
  • Stop on failed checks: before publishing, the site is checked for personal or secret information, links outside the allow list, invisible characters and details useful to attackers. If a check fails, nothing is published and the previous version stays online.
  • A person decides: the one who makes a change and the one who checks it are kept separate, and the operator reviews the diff before merging. Passing the checks is not proof of safety.

Link safety

  • Only pages of organisations on the allow list (governments, public bodies, international organisations, peer-reviewed journals and the like) are listed. No private or personal sites, short URLs or ads.
  • New links are checked to be official, not redirected to another domain and free of signs of tampering; only links with a check record are shown.
  • Weekly automatic check: certificate problems, broken links, redirects and signs of tampering (injected content, text that looks like instructions to an AI). With more than 800 links, four groups are checked one per week, covering everything every four weeks. Dangerous links are reported to the operator and removed or replaced with the new official URL.

Review routine

  • Twice a day: each publish runs data checks, privacy checks, commit checks, repository-settings checks and self-tests; any failure stops publishing.
  • Weekly: the link check above, a review of official security announcements (GitHub, Node.js, JPCERT/CC, IPA and others), and the operator's own check of the GitHub screens (unfamiliar sign-ins, apps, pull requests or branches).
  • Monthly (Japanese emergency care page): because it deals with life-threatening situations, an automatic check runs in the first week of each month, and then the operator opens every linked page and checks the content. Links that no person has checked yet are not shown; links whose monthly check is overdue stay on the page while the operator is reminded.
  • 45 days after the last update: GitHub stops scheduled jobs in repositories without updates for 60 days, so the operator is notified after 45 days.
  • When a new incident appears: it is checked for relevance to this site and handled if needed, and recorded below and in the security record.

AI helps with reviews, but AI only proposes; the operator decides. A review done by an AI is not called an independent audit.

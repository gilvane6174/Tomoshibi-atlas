# 掲載作業の手順（掲載担当）

## 変更するファイル（この2つだけ）

| ファイル | 内容 |
|---------|------|
| `data/curated/entries.json` | 「研究と対策」「こころ」「福祉」の掲載内容（最新情報） |
| `data/curated/changelog.json` | 更新履歴。追加・修正・削除のたびに1件追記する（サイトの説明ページに公開される） |

> `data/directory/links.json`（国・分野別の公式リンク集）は**運用者だけが管理する参照データ**。AI・bot は変更しない（CI が拒否する）。リンク切れや移転に気づいたら、変更せずに運用者へ報告する。

## リンクの安全基準

原典・関連リンクはすべて [LINK-SAFETY.md](LINK-SAFETY.md) の条件を満たすものだけにする（証明書の警告・リンク切れ・停止中・転送・改ざんの兆候があるページは使わない）。

## 使ってよい原典

- `peer_reviewed`：査読付き学術誌の論文
- `public_agency`：各国の公的機関（省庁、公衆衛生機関など）の発表
- `intl_org`：国際機関（WHO、OECD、ILO、国連など）の報告

使ってはいけないもの：個人ブログ、まとめサイト、SNS、企業の宣伝、査読前のプレプリント単独、AI が生成した文章、出典の確認できない数値。
リンクは `scripts/allowed-sources.json` の許可リストに一致する URL だけ（CI で自動検査）。`?` や `#` を含む URL は使えない。DOI リンクは主要な査読誌の出版社の番号に限る（それ以外は出版社のページの URL を使うか、運用者に追加を依頼）。

## 量と鮮度の上限（CI が拒否する）

- 1回の PR：追加・変更は10項目まで、削除は3項目まで、更新履歴の追記は3件まで、コミットは20件まで
- 追加・変更した項目の `checkedAt` と、新しい更新履歴の `date` は、原典を実際に開いて確認した日（日本時間の今日から3日前まで）
- 表示されなくなる項目（削除、または新しい項目によって「以前の情報」になるもの）は、合わせて3件まで
- 既存の項目の `layer`・`topic`・`countries` の変更と、`approved` タグは運用者だけ
- `ops/AI-PAUSE` が main にあるあいだは作業しない（緊急停止中）

## 悪用されうる情報を書かない（デュアルユース対策）

このサイトは、閲覧者が身を守るための情報を届ける場所であり、攻撃する側の手助けをしてはならない。

- 書かない：攻撃の手順、攻撃コード・実証コード（PoC）、IPアドレス・ドメイン・ファイルのハッシュ値などの痕跡情報（IOC）、未公開・未修正の脆弱性、被害を受けた個別の組織のシステム構成や弱点、ゼロデイの詳細
- 書いてよい：公的機関がすでに公表した事実の要約、影響を受ける製品の種類、利用者がとるべき対処（更新・設定確認など）と、その公式ページへのリンク
- セキュリティ以外でも同じ：薬物・毒物の作り方や、人を傷つける具体的な方法につながる記述は書かない
- 迷ったら書かない。CI の機械的な検査は一部しか止められないため、最後は運用者が差分を見て判断する

### 対策の公表を待つ（脆弱性・被害の報告情報）

- 脆弱性や攻撃被害などの報告情報は、**製品の提供元や国・公的機関から対策（修正版・回避策・注意喚起での対処方法）が公表されてから**反映する。対策が公表される前の情報は、どれだけ確かでも載せない
- 自動取得の CISA KEV は、CISA が対処方法（requiredAction）を示したものだけを載せる（`scripts/fetch-security.mjs` で、対処方法が空のものは除く）
- フォームや SNS などで、未公表の脆弱性・被害の情報を受け取っても掲載しない。内容を広めず、送り主には製品の提供元や IPA（情報処理推進機構）の届出窓口への連絡を案内する（返信する場合）
- このサイト自体の脆弱性の報告は SECURITY.md の手順で受け付け、修正するまで公開しない

## 項目の形式

```json
{
  "id": "research-2026-001",
  "layer": "research",
  "title": { "ja": "見出し（日本語）", "en": "Headline (English)" },
  "summary": { "ja": "原典の要点を自分の言葉で1〜2行", "en": "Same meaning in English, 1–2 lines" },
  "attribution": { "ja": "福祉は必須：OECD『〇〇』（2025年）によれば", "en": "Required for welfare: According to OECD, '…' (2025)" },
  "topic": "ai-diagnostic-imaging",
  "tags": ["ai", "early-stage"],
  "countries": ["JPN"],
  "placeBasis": "reported_country",
  "importance": "minor",
  "publishedAt": "2026-09-30",
  "checkedAt": "2026-10-25",
  "source": { "name": "原典の名称", "url": "https://..." },
  "sourceType": "peer_reviewed",
  "links": [{ "label": "補足リンクの名称", "url": "https://..." }]
}
```

| 項目 | ルール |
|------|-------|
| `id` | 英小文字・数字・ハイフン。分野名から始める（`research-`・`mental-`・`welfare-`） |
| `title`・`summary` | **日本語と英語の両方が必須**。見出し80字・要約200字以内。英語は日本語の意味をそのまま訳し、足したり省いたりしない |
| `topic` | 任意。同じ地域・同じ話題の続報に同じ値を付けると、古い方は公表日から7日間「以前の情報」と表示された後に消える |
| `tags` | `ransomware` `ai` `statistics` `support` `policy` `early-stage` のみ（`approved`＝規制当局の承認済み は運用者だけが付けられる） |
| `countries` | ISO 3166-1 alpha-3 の国コード。地域を特定しない場合は `[]` にし、`placeBasis` を `global` |
| `importance` | `minor` のみ。`major` への変更は運用者だけが行う（CI で拒否） |
| `publishedAt`・`checkedAt` | 原典の公表日／**実際に原典を開いて確認した日**。どちらも日本時間の今日より後は不可 |
| 先頭の `reviewedAt` | ファイル全体を最後に見直した日 |
| 例にない項目名 | 使えない（CI で拒否） |

## 今日の動物たち（`data/curated/animals.json`、運用者だけが変更）

- 毎日の組み立てで、日本時間の日付をもとに、この一覧から国が重ならないように20件を自動で選ぶ（`scripts/lib/animals.mjs`）。同じ日なら何度組み立てても同じ
- 1件＝1種類の動物と、やさしく意外な事実1つ。日本語は90文字以内（です・ます調）、英語は170文字以内で同じ意味
- **載せない**：死・狩り・捕食の場面・けが・病気・絶滅や減少の不安をあおる話・動物実験・ペットの売買・政治・宗教・食べ物としての話。検査（`validateAnimals`）でも一部の言葉を機械的に止める
- 原典は、許可リスト `animalHosts`（公的機関・公的な博物館や動物園・大学・ユネスコなど）のページだけ。事実は原典に書かれていること。国は原典に書かれた生息地から選ぶ
- 追加・変更は運用者の PR で行う（AI・bot の PR では変更できない。scope-guard が止める）。AI に候補を作らせる場合も、運用者が原典を開いて確かめてから入れる

## 書き方

### 共通
- 自分の言葉で1〜2行に要約し、原文の長い転載はしない
- 断定・誇大・優劣の表現を使わない（「治る」「効く」「効果がある」「必ず」「奇跡」「副作用はない」「最悪の国」、英語の cure / miracle / guarantee など。CI が語尾違いや全角・見えない文字によるすり抜けも検出するが、最終確認は運用者）
- 効果を書くときは「〇〇を対象とした研究で、△△の変化が報告された」の形
- 数値は原典の数値と時点をそのまま。自分で計算・推計しない
- 見えない文字・HTMLタグは使わない（CI で拒否）

### 研究と対策（research）
- AI を活用した研究・対策の成果も含める（`tags` に `ai`）
- 研究段階・臨床試験中・承認済みなどの段階を、原典で分かる範囲で明記する
- 一つの研究結果を一般化しない

### こころ（mental）
- 公的機関の統計と、公的な相談窓口・支援制度の情報のみ
- 自殺・自傷・摂食障がいなどについて、**具体的な手段・方法・量・場所は一切書かない**
- 不安をあおる表現を避ける

### 福祉（welfare）
- 制度の課題は必ず出典の見解として書き、`attribution` に出典主語を入れる（必須）
- サイト自身の評価、国の優劣、ランキング表現は書かない

## 更新履歴の書き方

```json
{ "date": "2026-10-25", "by": "ai-curator", "summary": { "ja": "研究と対策に1件追加", "en": "Added 1 item to Research & Response" }, "ids": ["research-2026-001"] }
```

- **末尾への追記のみ**。過去の記録は変更・削除・並べ替えしない（CI で拒否）
- `date` は日本時間の今日か昨日
- 追加・変更・削除した項目、および今回の変更で「以前の情報」や非表示になる項目の `id` をすべて `ids` に書く（CI で検査）
- `by` は AI・bot の場合 `ai-curator` か `bot-curator` だけ（CI が拒否する）。`operator` は運用者だけが使う。監査担当は更新履歴を書かない

## 手順

1. `main` の最新から、`curated/` で始まる作業ブランチを作る（例：`curated/2026-10-25`）。コミットの作者名は自分の GitHub ユーザー名、メールは GitHub の noreply アドレスにする。コミットメッセージに AI ツールが自動で付けるセッション情報の行（ツール名と Session の語を含む行や、AI との会話の URL）は入れない（CI が拒否する）
2. 2ファイルを編集する。既存の項目の `layer`・`topic`・`countries` は変えない（変更が必要なら運用者に依頼）
3. `node scripts/format-data.mjs` で書式を整える（CI が求める決まった書式になる）
4. `node scripts/validate-data.mjs` と `node scripts/check-privacy.mjs` を実行し、エラーゼロを確認
5. `AI_LOGIN=<自分のユーザー名> node scripts/check-my-pr.mjs` で、CI と同じ範囲・量・日付の検査を手元で行う（PR の宛先は必ず `main`）
6. PR を作り、テンプレートを全項目埋める
7. 監査担当（4種）と運用者のレビューを待つ。修正依頼には同じブランチで対応する。main が進んだら取り込む（rebase または merge）。確認から3日以上たって CI が日付で失敗したら、**原典を開き直して確認してから** `checkedAt` と更新履歴の日付を直す（日付だけを書き換えない）

## 週次の候補をまとめて追加する（`scripts/add-candidates.mjs`、v1.2.5〜）

週次の定期タスクが作る `candidates-<日付>.json`（`{"items":[…]}`、1ファイル10件まで）から、採用する項目だけを残して使う。

1. `node scripts/add-candidates.mjs <ファイル>`：確認だけ。完成予定の entries.json と changelog.json を一組で検査する（ファイルは変えない）
2. `node scripts/add-candidates.mjs <ファイル> --write`：追加する。AI・bot が実行するときは `--by ai-curator`（`operator` を使わない）
3. いつもどおり PR を作り、差分を読んでから取り込む

- 全体の最終確認日（`reviewedAt`）は**変えない**。新しい項目の `checkedAt` と更新履歴だけが新しくなる。全体を見直したときだけ、運用者が別に `reviewedAt` を更新する（AI・bot は変えられない）
- 書き込みの途中で失敗したら、ツールが元に戻す。強制終了などで「書き込み中」の印（`data/curated/.add-candidates-pending.json`）が残ったときは、`node scripts/add-candidates.mjs --restore` で戻す（印があるあいだは check-repo が失敗し、PR・公開できない）

## 表記のルール

- 「障害」は「障がい」と書く（例：障がい者福祉、発達障がい、摂食障がい）。システムの故障などの意味では「不具合」「トラブル」を使う
- 人の病気・こころの状態について、機械やシステムの故障にたとえる表現は使わない

## 表示件数（20〜50件。上限は2026-10-26 に25件から30件へ、2026-10-27 に50件へ変更。今日の動物たちは毎日20件）
- 各分野の表示は、おおむね20〜50件にそろえる（`scripts/importance-rules.mjs` の `fitCount`／`SHOW`）。
- 自動取得の分野：通常の掲載期間内を新しい順に最大50件。20件に満たないときは、`fillDays` 以内の古い情報を小さな文字で補う。
- 手動掲載の分野：研究と対策・こころと福祉は新しい順に最大50件、防犯・防災は90日以内の新しい順に最大50件（20件に満たないときは180日以内で補う。自動取得の見出しは情報源ごとの上限 maxShown つき）。地震は USGS の自動取得だけで、過去30日を新しい順に最大50件。新しい項目を追加すると、古い項目から自動で表示を外れる（entries.json からは消さない）。
- 20件を保つため、手動掲載の分野は月に数件ずつ、公式の原典で確認した新しい項目を追加する（追加の決まりはこの文書の前半と同じ）。
- 元の情報源に公表が足りないときは、件数が20件より少なくてよい。件数をそろえるために情報を作ったり、無関係な情報で埋めたりしない。
- 件数のルールを変えたら、site/about.html・about.en.html の「表示する件数」も同じ内容に直す。

## AI と SI（Super Intelligence）の表記
- 米国の大統領令14434号（2026年9月29日署名、原文 https://www.whitehouse.gov/presidential-actions/2026/09/inaugurating-the-era-of-super-intelligence/ ）で、米国の行政機関の公式な文書などの「AI（artificial intelligence）」を「SI（Super Intelligence）」と呼び替えるよう指示した。SI と書かれた情報も、AI 関連の情報として拾う（tags に `ai`）。
- 「SI」だけでは、国際単位系・システムインテグレーター・国コード（スロベニア）などと区別できない。掲載文では必ず「SI（Super Intelligence。米国政府の文書でのAIの呼び方）」「Super Intelligence (SI), the US federal government's term for AI」のように説明を添える（`scripts/validate-data.mjs` が検査）。
- 原典が SI と書いていても、意味が AI と同じかどうかは原典の文脈で確かめる。推測で AI 関連にしない。
- 原典の呼び方（SI）を本サイトの言葉で「AI」と言い換える場合は、「（原典ではSI）」と添える。どちらの呼び方が正しいかの評価はしない。

## 分野の構成（2026-10-26 変更）
- 「こころ」と「福祉」は画面上で「こころと福祉」に統合した。データ（entries.json）の layer は従来どおり `mental` / `welfare` のまま書き、組み立て時に一つの分野にまとめる（画面では元の分類を小さく表示）。福祉の項目は従来どおり attribution 必須。
- 「研究と対策」には、医療・AI（SI）の研究に加え、次の**公式の対策**も載せる：ITやAIのセキュリティ更新（パッチ配布・回避策。修正の公表後に限る。開発元の公式発表は sourceType `vendor`）、防災の新しい指針・警報のしくみ、防犯・詐欺対策の新しい施策。tags は `security` / `disaster` / `crime`。
- 「防犯」（layer `crime`）には犯罪・詐欺・闇バイトなどの**注意喚起と統計**、「防災」（layer `disaster`）には**災害の被害状況**を載せる。対策の発表は「研究と対策」へ。地震は「地震」の分野（USGS の自動取得）だけに出す（2026-10-26 変更：地震が多いと防犯の注意喚起が流れてしまうため、3つに分けた）。
  - 数値は公式の発表どおりに書き、「〇〇の発表によれば」の形にする。読み取れない数値は書かない。
  - 個人の名前、手口の細部、被害者・容疑者を特定できる情報は書かない。
  - 緊急時の情報源と誤解されないよう、見出しに「速報」「至急」などの言葉を使わない。
  - 地震は USGS から自動取得するため、個別の地震を手動で追加しない（被害状況の公的な報告は追加してよい）。

## 自動取得の見出し（RSS）の追加ルール
- 追加できるのは、利用条件を一次情報で確認できた公的機関の RSS/Atom だけ。`scripts/allowed-sources.json` の `enabledFetchers` で個別に有効化し、確認日と根拠を docs/SOURCES.md に書く
- 日本の省庁の RSS は、RSS の案内ページに「その情報に基づいたホームページの作成・再配布は固くお断り」などの記載がないかを必ず確かめる（厚生労働省・警察庁・内閣府にはこの記載があるため使わない）
- 表示するのは見出し・公表日・リンク・発表した機関の国だけ。本文は取得しない。見出しは原文のまま（機械翻訳しない）
- 1つの情報源が分野を埋め尽くさないよう、情報源ごとの表示上限（`maxShown`）を決める

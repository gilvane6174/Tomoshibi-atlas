# 役割分担と権限

複数の AI・bot で運用する場合、**書く者と確認する者を分ける**。同じ AI・bot が自分の作業を監査しない。
最後の判断（マージ＝公開）は必ず運用者（人間）が行う。

## 役割

| 役割 | `by` に書く名前 | すること | してはいけないこと |
|------|----------------|---------|-------------------|
| 掲載担当（curator） | `ai-curator` / `bot-curator` | 原典を確認し、`entries.json` と `changelog.json` を更新して PR を作る | 監査・承認・マージ。2ファイル以外の変更 |
| セキュリティ監査（security） | `ai-security-audit` | PR の差分を `AUDITS.md` のセキュリティ項目で確認し、指摘をレビューコメントで返す | ファイルの変更。PR の承認 |
| 情報監査・ファクトチェック（fact） | `ai-fact-check` | 要約が原典と一致するか、数値・日付・出典を照合する | 同上 |
| 翻訳監査（translation） | `ai-translation-audit` | 日本語と英語の意味が一致し、誤解を生まないか確認する | 同上 |
| 偏り・誤情報監査（balance） | `ai-balance-audit` | 断定・誇大・偏った表現、誤情報・偽情報の可能性を確認する | 同上 |
| 運用者（operator） | `operator` | 監査結果を見て、承認・修正依頼・却下を決める。手順書と設定の変更 | ― |

- 監査は4種すべてを、掲載担当とは**別の** AI・bot が行う（1つの AI が複数の監査を兼ねるのはよい。ただし自分が書いた PR は監査しない）
- `by` には役割名だけを書く。AI の製品名・アカウント名・個人名は書かない（`changelog.json` は公開される）
- 監査担当は「問題なし」でも、確認した項目と確認できなかった項目を必ず書く

## 権限（GitHub）

| 主体 | 権限 |
|------|------|
| 運用者 | リポジトリの管理者 |
| 掲載担当の AI・bot | 専用アカウント。Contents と Pull requests の書き込みのみ（Workflows・Secrets・管理権限なし）。push できるのは `curated/` ブランチだけ（ルールセット）。CI の範囲検査で2ファイル以外は拒否される |
| 監査担当の AI・bot | 読み取りと PR へのコメントのみ（書き込み権限は不要。付けない） |

設定方法は `docs/GITHUB-SETTINGS.md`。

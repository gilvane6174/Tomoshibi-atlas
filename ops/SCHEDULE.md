# 作業時刻とアクセスの制限

同じサイトに何度もアクセスすると、相手に負担をかけ、スパムや攻撃と判定されるおそれがあります。
そのため、作業の時刻と回数をあらかじめ決めています。

## 自動取得（GitHub Actions・AI不使用）

| 内容 | 時刻 | 回数 |
|------|------|------|
| WHO・CISA・USGS と公的機関の見出し（JPCERT/CC・IPA・NCSC・金融庁・FTC・消防庁・NASA・NIH）を取得して公開 | 毎日 05:43 と 17:43（日本時間、1日2回）※ GitHub の混雑で数十分遅れることがある | 各情報源へ原則1回ずつ（WHO・CISA は失敗時だけ予備の取得先へ1回。最大2回） |
| 運用者が `main` を更新したとき | 更新の直後 | 各情報源へ原則1回ずつ（WHO・CISA は失敗時だけ予備の取得先へ1回。最大2回） |
| 手動実行（Run workflow） | 運用者が必要なときだけ | 1日に数回まで |

時刻を変える場合は `.github/workflows/deploy.yml` の `cron`（協定世界時で記載）と、このファイルを同時に直す。

## AI・bot の作業（掲載・監査）

| 項目 | ルール |
|------|-------|
| 作業してよい時間 | 運用者が開始を指示したときだけ。自動で定期実行する場合も **1日1回まで**、日本時間の 9:00〜21:00 の間 |
| 1回の作業で開いてよいページ数 | 原典と、その確認に必要なページ。目安は **30ページまで** |
| 同じページへのアクセス | **1日1回まで**（読み込んだ内容は作業中は使い回す） |
| アクセスの間隔 | 同じサイトへは **10秒以上** あける |
| 禁止 | 一覧ページの総当たり取得（クロール）、ログインが必要なページ、有料記事の回避、`robots.txt` や利用規約で禁止されている取得、自動でのフォーム送信 |
| 名乗り方 | 製品の標準のまま。運用者の個人情報や連絡先を通信に含めない |

## 人間（運用者）の作業

- 掲載内容の確認・承認は、運用者の都合と体調に合わせて**不定期**に行う。決まった時刻に更新されない
- このため、サイトの免責事項に「更新は即時ではなく、運用者の都合や体調によって不定期」と明記している

> **注意**：上の時刻・回数・間隔の制限は、GitHub の仕組みでは機械的に強制できない（PR 単位の量の上限だけは CI が強制する）。運用者が AI・bot 側の実行設定（定時実行の回数・アクセス間隔）で守らせ、守られていない場合は ops/AI-PAUSE で止める。
